# Splunk Boss of the SOC v1 (BOTS)

Logs from a small company network ("Wayne Enterprises") in August 2016, during two real attacks staged by
Splunk for its Boss of the SOC capture-the-flag: the defacement of the web site `imreallynotbatman.com` by the
Po1s0n1vy group, and a Cerber ransomware infection of the desktop `we8105desk`. There are Windows event logs,
Sysmon, registry, FortiGate firewall, IIS, Suricata IDS, Nessus and Splunk Stream network captures, from
about 2016-08-01 to 2016-08-28.

The workload is needle in a haystack: hunting for one IP, host, file hash, domain or command line, often as a
substring, in tens of millions of events. Research notes are in
[CANDIDATE_DATASETS.md](../CANDIDATE_DATASETS.md#needle-in-a-haystack).

Generated by `bots/bots.py`.

## Source

[splunk/botsv1](https://github.com/splunk/botsv1): the JSON export, one gzip file per Splunk sourcetype at
`https://s3.amazonaws.com/botsdataset/botsv1/json-by-sourcetype/`, 6.7 GB compressed. Each line is a Splunk
search result, `{"preview": false, "result": {...}}`, whose fields are strings, or arrays of strings for
multi-valued fields (named with a `{}` suffix, such as `cs_version{}`).

## Tables

Namespace `bots_sf<N>`. One table per sourcetype:

| Table | Sourcetype |
|---|---|
| `wineventlog_application`, `wineventlog_security`, `wineventlog_system` | `WinEventLog:*` |
| `sysmon` | `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational` |
| `winregistry` | `WinRegistry` |
| `fgt_event`, `fgt_traffic`, `fgt_utm` | FortiGate firewall |
| `iis` | IIS web server |
| `nessus_scan` | `nessus:scan` |
| `stream_dhcp`, `stream_dns`, `stream_http`, `stream_icmp`, `stream_ip`, `stream_ldap`, `stream_mapi`, `stream_sip`, `stream_smb`, `stream_snmp`, `stream_tcp` | Splunk Stream `stream:*` |
| `suricata` | Suricata IDS |

Every table has:

- `_time TIMESTAMPTZ`: the event time, in UTC with microseconds where Splunk has them. Splunk shows it in MDT
  (UTC-6), so `2016-08-10 15:30 MDT` is `2016-08-10 21:30 UTC`.
- `_raw VARCHAR`: the original log line, which many hunts search directly.
- A column for every field of the sourcetype, as Splunk extracted it with the add-ons BOTS was built with.

Columns are listed in `bots/fields.csv` (table, column, type, source fields) and in `bots/sf<N>/schema/`:

- Names are lower case snake_case: `CommandLine` is `commandline`, `ports{}.port` is `ports_port`.
  A reserved word gets a trailing `_` (`user_`, `from_`), and names are cut to 63 characters.
- A field and its multi-valued form (`cs_version` and `cs_version{}`) never occur in the same event, so they
  share a column. Multiple values are joined with newlines.
- Fields that differ only in case are different fields, such as Sysmon's `Signature` (the code signer) and
  Splunk's `signature` (the event description). The all-lower-case one is Splunk's and is prefixed `cim_`.
- A column is `BIGINT` or `DOUBLE` when every value of it is an integer or decimal, else `VARCHAR`.
  Times inside the logs (`UtcTime`, `TimeCreated`) stay text, as they mix time zones.
- Splunk's own index fields (`_bkt`, `_cd`, `_serial`, `punct`, `linecount`, `date_*`, `eventtype`, `tag`,
  `index`, `splunk_server`, `sourcetype`) are left out.

Some columns are Splunk extractions from attacker input, such as the IIS columns named after URL query
parameters of the web scanner (`do_`, `full_`, `cmd`). They are kept, as a hunter in Splunk sees them.

## Scale Factors

SF1 is BOTS as published. SF N adds N - 1 copies of the haystack, as other branch offices of the company:

- The attack events are not copied, so the needles, and the answers to the BOTS questions, are the same at
  every scale factor. They are the events of Splunk's
  ["attack only" set](https://s3.amazonaws.com/botsdataset/botsv1/botsv1-attack-only.tgz), 955,807 events, which
  are exactly the events of the full set in Splunk index buckets 28 and 48 (`_bkt`), checked per sourcetype.
- Copy k (2 to N) moves internal addresses from `192.168.a.b` to `10.k.a.b`, and adds `-k`, as three digits, to internal host
  names (`we1149srv` becomes `we1149srv-002`), in every text column including `_raw`. External addresses,
  times, users, GUIDs and hashes are unchanged.
- Each copy is a separate chunk of parts, in time order, after the original.

## Bucket Layout and Generating

```text
bots/sf<N>/<table>/<table>[_NNNN].{parquet,csv.zip}
bots/sf<N>/schema/
```

```bash
uv run generate.py bots --extract-fields            # profile the source; write fields.csv and the schema of SF1 and SF10
uv run generate.py bots --sf 1
uv run generate.py bots --sf 10 sysmon stream_http
```

Published scale factors: SF1 and SF10. Tables are loaded through a DuckDB database file per scale factor in
`temp/bots/`, since `wineventlog_security` does not fit in memory, so scale factors can run in parallel once the
source files are downloaded.
