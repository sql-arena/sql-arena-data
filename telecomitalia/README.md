# Telecom Italia Big Data Challenge (CDR)

Mobile phone activity for Milan and the Province of Trentino, November and December 2013, released by
Telecom Italia for the [Big Data Challenge](https://theodi.fbk.eu/openbigdata). Call, SMS and
internet activity is aggregated per grid square in 10-minute slots. The set also has square-to-square
and square-to-province interactions. It is aggregated CDR data: there are no individual calls or subscribers.

Described in Barlacchi et al., ["A multi-source dataset of urban life in the city of Milan and the
Province of Trentino"](https://pmc.ncbi.nlm.nih.gov/articles/PMC4622222/) (Scientific Data, 2015).

Generated by `telecomitalia/telecomitalia.py`. Research notes are in
[CANDIDATE_DATASETS.md](../CANDIDATE_DATASETS.md).

## Prerequisite: Dataverse API token

The telecom files are behind a Dataverse guestbook, so anonymous downloads fail with
`400 "You may not download this file without the required Guestbook response"`. Downloading needs
a Harvard Dataverse account and its API token. The token must be in the environment variable
`DATAVERSE_API_TOKEN`:

```sh
# In ~/.zshenv (read by every zsh, including non-interactive ones); keep the file chmod 600
export DATAVERSE_API_TOKEN=<your token>
```

Never commit the token to this repository.

To get a token, sign up at <https://dataverse.harvard.edu>. Then open your account name in the navbar,
choose API Token and click Create Token. This one-time step cannot be automated. Tokens expire after
one year. To check or renew one:

```sh
curl -H "X-Dataverse-key:$DATAVERSE_API_TOKEN" https://dataverse.harvard.edu/api/users/token
curl -H "X-Dataverse-key:$DATAVERSE_API_TOKEN" -X POST "https://dataverse.harvard.edu/api/users/token/recreate?returnExpiration=true"
```

### On EC2: SSM parameter

When `DATAVERSE_API_TOKEN` is not set, the generator reads the token from the SecureString SSM parameter
`/sql-arena/dataverse-api-token` in `eu-north-1` (override with `DATAVERSE_TOKEN_PARAMETER` and
`DATAVERSE_TOKEN_REGION`). The instance role needs `ssm:GetParameter` on that parameter. To create it,
or to update it after renewing the token (add `--overwrite`):

```sh
aws ssm put-parameter --profile sql-arena --region eu-north-1 --type SecureString \
  --name /sql-arena/dataverse-api-token --value "$DATAVERSE_API_TOKEN"
```

## Download flow

1. List a dataset's files, with no auth needed:
   `GET https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:<DOI>`.
   This returns each file's `id`, `filename` and `filesize`.
2. Submit the guestbook response and get a signed URL:
   `POST /api/access/datafile/<id>?signed=true` with header `X-Dataverse-key: $DATAVERSE_API_TOKEN`
   and body `{"guestbookResponse": {}}`. The email defaults to the account's. The response is
   `{"data": {"signedUrl": "..."}}`; the URL is valid for a few minutes.
3. `GET` the signed URL, following redirects. Single `Range` requests work, so interrupted downloads can resume.

## File layout

Tab separated, no header. `time_interval` is the start of the 10-minute slot in epoch milliseconds
(UTC). Activity values are scaled by an undisclosed constant, so they are relative, not counts. Rows
with no activity are omitted and missing measures are empty fields.

- `sms-call-internet-{mi,tn}-YYYY-MM-DD.txt`:
  `square_id, time_interval, country_code, sms_in, sms_out, call_in, call_out, internet`.
  Checked against the first MI file (~4.3M rows per day at ~75 bytes per row).
- `MItoMI-*.txt` / `TNtoTN-*.txt`: `time_interval, square_id_1, square_id_2, strength`.
- `{mi,tn}-to-provinces-*.txt`: `square_id, province, time_interval, cell_to_province, province_to_cell`.

The MItoMI, TNtoTN and province layouts come from the paper and are not yet checked against a file.
The Milan grid has 10,000 squares (100 x 100, ~235 m); the Trentino grid has 6,575.

## Tables

| Table | Source | Columns | Sorted by |
|---|---|---|---|
| `sms_call_internet_mi`, `sms_call_internet_tn` | `sms-call-internet-{mi,tn}-*.txt` | `square_id INT`, `time_interval TIMESTAMP`, `country_code INT` (all NOT NULL), `sms_in`, `sms_out`, `call_in`, `call_out`, `internet DOUBLE` | all columns, time first |
| `mi_to_mi`, `tn_to_tn` | `MItoMI-*.txt`, `TNtoTN-*.txt` | `time_interval TIMESTAMP`, `square_id_1 INT`, `square_id_2 INT`, `strength DOUBLE` (all NOT NULL) | all columns, time first |
| `mi_to_provinces`, `tn_to_provinces` | `{mi,tn}-to-provinces-*.txt` | `time_interval TIMESTAMP`, `square_id INT`, `province VARCHAR` (NOT NULL), `cell_to_province`, `province_to_cell DOUBLE` | all columns, time first |
| `grid_mi`, `grid_tn` | `milano-grid.geojson`, `trentino-grid.geojson` | `square_id INT`, `geometry_wkt VARCHAR` (the square as a WKT polygon in EPSG:4326), `centroid_lon`, `centroid_lat DOUBLE` (all NOT NULL) | `square_id` |

`time_interval` is the start of the 10-minute slot in UTC, converted from epoch milliseconds. A daily file covers its day in Italian time, e.g. the 2013-11-01 file runs from 2013-10-31 23:00 to 2013-11-01 22:50 UTC. Trentino square ids run from 38 to 11454, not 1 to 6575.

Country code 0 is not explained in the source documentation we have read, and it carries a large share of the activity: about 41% of Milan call activity in a two-day sample. Code 39 is Italy. Queries that look at roaming leave out both.

## Bucket Layout

```text
telecomitalia/<table>/<table>.{parquet,csv.zip}           # the grids
telecomitalia/<table>/<table>_NNNN.{parquet,csv.zip}      # the activity tables
telecomitalia/<table>/_manifest.json                      # parts written, for resuming
telecomitalia/queries/, telecomitalia/schema/             # checked-in queries and DDL
```

## Generating

```bash
uv run generate.py telecomitalia                                  # all tables, ~717 GB download
uv run generate.py telecomitalia grid_mi tn_to_provinces --until 2013-11-07 --chunk-gb 0.3 --no-upload
```

The token comes from `DATAVERSE_API_TOKEN` or, on EC2, the SSM parameter (see above). With Docker, pass the variable through with `-e DATAVERSE_API_TOKEN`.

The 62 daily files of a table are grouped into chunks of consecutive days of up to `--chunk-gb` source (default 8 GB). That makes one chunk per day for `mi_to_mi` and `tn_to_tn`. Each chunk is loaded into DuckDB, validated and sorted, then exported as parquet parts of about `--target-mb` (default 500 MB). The parts of a table cover consecutive time ranges. The last part of each chunk is smaller.

Each file is downloaded through the guestbook with a fresh signed URL per attempt. An interrupted download resumes with a Range request, and every file is checked against the md5 Dataverse publishes. `--downloads` (default 4) files download in parallel, and the next chunk downloads while the current one is exported. Expect the download, not the export, to set the pace. Run it on EC2, with disk for two chunks plus DuckDB spill (about 50 GB).

## Validation

Loading is strict: every line must have the expected number of fields and types, and the key columns must be present. One source file is known to be cut off mid-line: `tn-to-provinces-2013-11-18.txt` ends after 24,772,608 bytes, and its md5 matches Dataverse, so the file itself is truncated. Its partial last line is skipped and logged. Any other rejected line stops the run.

## Restarting

`_manifest.json` records the parts uploaded per chunk. A rerun skips complete tables and chunks and resumes a chunk at its first missing part. `--until` stops after the chunks up to that day; the table is only marked complete once every chunk is done. Only whole chunks are generated, so for a short test range also lower `--chunk-gb`: with the default 8 GB, the first chunk of most tables spans several weeks and nothing before `--until` is written.

## Queries

`telecomitalia/queries/q01.sql` to `q15.sql` were written by hand for this repo, because the dataset comes with no query set. They cover:
- daily and hourly rollups
- top squares joined to the grid
- the roaming country mix
- MI-to-MI origin-destination pairs with centroid distance
- the share of traffic that stays within a square
- province flows in Milan versus Trentino
- the New Year's Eve 10-minute window
- weekend-heavy squares and Trentino foreign hotspots
- TN-to-TN strength by distance band
- the peak 10-minute slot per hour
- daily slot and square completeness

Italian time is `time_interval + INTERVAL '1' HOUR`: CET all through November and December 2013, with no DST change. Each run uploads them unchanged to `telecomitalia/queries/`.

## Schema

The DDL is checked in at `telecomitalia/schema/` (one `<table>.sql` per table, plus `keys.sql` where keys apply) and uploaded unchanged with each run.
